# 界面设计（UI）

本文件定义三个前端如何呈现信息。操作流程和反馈时机由 [UX 设计](ux.md)定义，精确终端行为由[终端规范](../spec/terminal.md)规定，界面所需数据由[应用接口规范](../spec/application-interface.md)提供。

## 对标目标与范围

体验参照见[产品定义](product.md#前端对标目标)。终端以 Codex CLI 的清楚对话层次和持续可编辑输入区为参照；Web 以 DeepSeek Harness Web 的工作区/会话导航、集中对话、执行轨迹和克制视觉为参照。参照用于确定体验方向，不复制其品牌资源，也不把本项目尚未具备的插件、制品预览或多工作区能力做成无实际功能的控件。

三个前端共享同一应用接口，但布局可以不同。任何前端都只能展示应用接口能够确认的事实，缺少能力或数据时隐藏对应项或明确说明，不能编造推理强度、限额、上下文比例、执行进度或操作结果。

## 共享信息层次

| 信息 | 呈现方式 | 目的 |
|---|---|---|
| 工作上下文 | 展示项目、模型、权限模式和会话身份；模型支持时显示推理强度 | 让用户知道正在什么环境里工作 |
| 用户输入 | 使用清楚的起点或消息容器，与回复留出间距 | 能在长历史中找到用户意图 |
| 助手回复 | 正文使用主要前景色，保留段落、列表和代码块层次 | 保证长文本可读 |
| 推理内容 | 使用次要样式并允许收起，弱于正式回复 | 避免与结果正文混淆 |
| 工具活动 | 单独标明操作名称、输入摘要、执行状态和必要结果 | 让用户识别和审查外部操作 |
| 审批请求 | 独立成块，展示操作、范围、原因及决策选项 | 在执行前提供足够判断信息 |
| 进展和结束状态 | 以简短文字标识连接、处理、完成、取消或失败 | 不依赖颜色猜测状态 |
| 后续输入 | 展示其中途引导或排队意图及接纳状态 | 避免与当前执行内容混淆 |

工作上下文不在每条消息中重复。已提交历史、尚未提交的流式内容、草稿和界面反馈必须保持可辨识；新输出不能覆盖草稿，审批期间仍能辨认原任务和当前操作。

## Web 信息架构

### 页面区域

Web 使用“左侧导航 + 中央任务工作区”的单页结构，不设置没有数据支撑的常驻右栏。桌面端侧栏保持可见，中央对话有稳定的阅读宽度；窄屏将同一侧栏转换为可关闭抽屉，而不是直接删除导航能力。

| 区域 | 内容与层级 | 组件要求 |
|---|---|---|
| 品牌与会话导航 | 产品标识、新会话主入口、最近会话、当前工作区和模型摘要 | 当前会话有明确选中态；会话标题单行截断但保留完整提示；列表独立滚动 |
| 顶栏 | 移动导航按钮、当前会话标题、连接/运行状态、用量与设置入口 | 高度紧凑，不与正文争夺注意力；状态同时有文字和图形标识 |
| 对话工作区 | 欢迎/空状态、用户消息、助手回复、推理、工具活动、错误与恢复入口 | 内容列居中并限制最大阅读宽度；流式内容沿用同一消息结构，不重复追加 |
| 审批区 | 当前操作、影响范围、原因、批次和审批动作 | 位于对话之后、输入区之前的显著位置；提交期间锁定同组动作 |
| 输入区 | 多行草稿、权限模式、发送/引导、排队与停止 | 保持底部可用；主要动作与次要动作层级明确；运行中仍可编辑 |
| 配置与反馈 | 模型/凭据对话框、轻量操作回执、连接错误和重试入口 | 对话框有明确标题和关闭方式；短暂回执不代替持久错误 |

### 导航方式

- 新会话是侧栏最明确的动作；最近会话按应用返回顺序呈现，点击后等待恢复成功再展示新环境。
- 当前会话同时使用选中背景、标记和可访问性状态表达，不只改变文字颜色。
- 移动端通过顶栏按钮打开会话抽屉，选择会话或关闭按钮后收起；抽屉打开时提供遮罩并阻止背景误操作。
- 设置使用模态对话框。没有应用接口支持的插件、工作区切换、制品预览和自动化入口不显示。

### 对话与执行轨迹

用户消息采用克制的气泡容器，助手正文使用完整阅读宽度。助手身份标签弱化，不以重复头像和大卡片分割长对话。推理内容默认折叠为“思考过程”，工具调用以紧凑活动条目呈现，名称、参数摘要和结果具有不同层级；长结果可展开查看，默认不挤占整页。

空会话展示简短欢迎语、当前工作范围提示和少量可执行示例。示例只帮助开始任务，不伪造历史消息。流式等待使用与正文位置一致的光标或活动指示，不以整页遮罩阻断阅读和取消。

### 输入与操作层级

输入框是页面最主要的交互容器。草稿区自动增高但限制最大高度，之后内部滚动。发送是唯一实心主按钮；运行中原位置切换为“引导”，排队为次按钮，停止为危险语义按钮。权限模式、记忆和模型等上下文控制保持紧凑，并在数据不可用时隐藏或禁用，不能提供看似可用但必然失败的入口。

Enter 提交、Shift+Enter 换行；中文输入法组合期间 Enter 不提交。运行中的引导与排队共用草稿但必须有不同的受理反馈。所有动作在请求期间显示进行中状态并防止重复提交，失败后恢复草稿和可用状态。

## Web 视觉规范

### 设计原则

- 以中性色、清楚边界和留白建立层级，以单一蓝色作为品牌与主要操作强调色；不使用渐变、装饰性光晕或大面积彩色卡片。
- 页面背景、侧栏、次级表面和悬浮表面分层但对比克制。边框优先于阴影，阴影只用于抽屉、对话框和轻量回执。
- 颜色不是状态的唯一载体。成功、警告、错误、连接中断和运行中都同时提供文字或图标。
- 明暗主题遵循系统偏好并共享语义令牌；任一主题都保持正文、次要文字、边框和焦点环可读。

### 配色语义

| 令牌语义 | 用途 |
|---|---|
| 页面背景 | 中央对话和全局底色 |
| 导航/组件表面 | 侧栏、输入区、工具条目和次级内容 |
| 主要/次要文字 | 正文与辅助信息，次要文字仍需满足可读性 |
| 边界/强边界 | 默认分隔与悬停、选中分隔 |
| 品牌强调 | 主按钮、当前会话、焦点和运行活动 |
| 成功/警告/危险 | 已完成、待审批/注意、失败/停止；均配文字 |

### 字体与排版

- 正文使用系统无衬线字体栈，中文回退到 PingFang SC、Microsoft YaHei 等；工具参数、代码、路径和 token 计数使用系统等宽字体栈。
- 默认正文 14px、行高不低于 1.6；助手长文可使用 15px。页面欢迎标题不超过 28px，区域标题 13–16px，辅助文字不小于 12px。
- 正文最大阅读宽度约 760–840px；长单词、路径和代码允许在容器内换行或横向滚动，不能撑破移动端视口。

### 间距、圆角与控件

- 采用 4px 基础间距网格，常用间距为 4、8、12、16、24、32px。
- 小控件圆角 6–8px，消息与输入容器 10–14px；避免所有内容都使用胶囊形容器。
- 桌面控件保持紧凑，触控端主要按钮和导航目标至少 44px 高或提供等效点击区域。
- 所有可交互元素具有默认、悬停、焦点可见、按下、禁用和请求中状态；焦点环不能被全局样式移除。

## Web 状态与反馈

| 状态 | 必须呈现 | 禁止表现 |
|---|---|---|
| 首次加载 | 对话和会话列表的结构化骨架或明确加载文字，输入暂不伪造可用 | 空白页、把加载显示为“没有会话” |
| 空会话/空列表 | 下一步说明和有效入口 | 只有空白或含糊的“无数据” |
| 流式运行 | 当前活动文字、流式光标、停止入口及可编辑草稿 | 以固定百分比推断进度 |
| 操作请求中 | 对应按钮禁用并显示受理中，审批同组锁定 | 重复提交、提前显示成功 |
| 受理/完成 | 与应用回执一致的轻量反馈 | 把按钮点击当作已接纳或已取消 |
| 空错误/取消 | 明确的完成或取消文字，保留已发生历史 | 将取消显示为失败或成功完成 |
| 请求失败 | 保留上下文的错误条、可理解原因及可行的重试/恢复动作 | 只用短暂 toast、丢失草稿 |
| 事件流断开 | 持久连接状态与自动重连说明，恢复后以快照重建 | 静默离线、重新提交任务来恢复界面 |
| 数据部分缺失 | 隐藏未知值或标注未提供，保留其他可用内容 | 用默认值编造模型、推理强度或工作区事实 |

## Web 响应式与可访问性

- 宽屏保持侧栏和居中内容列；中窄屏收缩间距；移动端侧栏转为抽屉，顶栏只保留高优先级动作，输入区适配安全区和屏幕键盘。
- 使用动态视口高度时提供回退；页面不得产生横向滚动。代码块和长结果在自身容器内滚动。
- 语义结构包含导航、主内容、对话日志、表单和对话框；图标按钮有可访问名称，当前会话和展开状态使用相应 ARIA 状态。
- 对话流使用礼貌级别的实时区域，状态错误可被辅助技术感知；避免每个流式分片都造成过度播报。
- 模态框打开后焦点进入，关闭后回到触发按钮；Escape 优先关闭模态框或移动抽屉，不能在这些界面之上误取消任务。
- 尊重 `prefers-reduced-motion`，减少脉冲、滚动和过渡动画；键盘路径与鼠标/触摸路径具备相同能力。

## 终端界面

### 布局基线

终端采用“对话内容、当前活动、输入编辑、状态提示”的结构。已提交内容进入终端滚动历史，当前活动和输入区在最新内容之后保持可用，输入区下方展示状态与上下文提示。运行中输入仍可编辑；新输出不能覆盖草稿，审批期间也能辨认原任务和当前操作。

本阶段采用保留终端滚动历史的交互形态，当前输入和状态组成可更新的交互区，不要求全屏备用屏幕。具体键位、刷新、换行和缩放由终端规范细化。

### 空闲与开始工作

```text
Super Agent   项目：当前项目

  对话历史和已完成的工具活动

────────────────────────────────────────
❯ 描述任务或输入命令
────────────────────────────────────────
模型：当前模型 · 权限：当前模式 · 空闲
```

### 执行中的界面

```text
❯ 修复失败的测试

● 我会先定位失败原因。

  工具 · 读取相关文件 · 已完成
  结果 · 已取得文件内容

  工具 · 运行测试 · 执行中

────────────────────────────────────────
❯ 先不要改动公共接口
────────────────────────────────────────
执行中 · 输入可继续编辑 · 提交方式见操作提示
```

### 审批界面

```text
需要审批 · 执行操作

操作：请求执行的具体操作
范围：涉及的目录或文件
原因：需要本次审批的原因

1. 允许一次
2. 始终允许
3. 拒绝

请选择：
```

### 后续输入与结束

中途引导和排队输入使用可区分标签，已提交与已接纳是不同状态。取消时明确显示“本轮已取消”，有已发生的操作时保留其记录；失败显示错误说明与必要上下文，不显示成功样式。是否可以继续输入由应用状态决定。

### 终端视觉规则

界面采用终端默认前景色，以及 ANSI 青色、绿色、红色和品红色；不构造 RGB、十六进制或索引颜色，也不使用蓝色或黄色前景色。语法高亮拥有独立主题。

- 默认前景色承载主要正文，青色用于可操作提示和结构标识。
- 品红色用于区分 Agent 活动与辅助状态，绿色表示成功，红色表示错误；同时保留明确文字。
- 推理和补充信息使用弱化样式，不降低正式结果的可读性。

颜色关闭或终端配色改变时，结构、文字标识和状态仍应可理解。长路径、长结果和窄窗口应保持内容顺序清楚，不因截断隐藏决定操作风险所必需的信息。

## 设计与实现的边界

本文件拥有布局、信息层次、视觉语义和界面示意。精确按键、刷新、通道结束、输入编码与输出去重属于 Spec，不在这里重复定义。待完成工作及其推进情况由 [Gap](../gap.md)与 [Flow](../flow.md)维护。
