# 产品定义

## 产品定位

Super Agent 是面向本地项目开发的交互式命令行 Agent。用户提出工作目标，系统结合会话与项目上下文，协调模型推理、工具操作和人工审批，返回回答或工作成果。

项目目的见[项目愿景](vision.md)，业务组成与交互边界见[软件架构](software-architecture.md)，前端呈现与使用流程见 [UI 设计](ui.md)和 [UX 设计](ux.md)。

## 前端对标目标

终端体验主要对标 Codex CLI；本机 Web 体验主要对标 DeepSeek Harness Web，借鉴其工作区与会话导航、集中式任务对话、清晰的执行轨迹，以及简洁专业的信息层级。具体呈现由 [UI 设计](ui.md)定义，任务操作和反馈由 [UX 设计](ux.md)定义。这些是对标方向，不代表承诺复制参照产品的全部平台、服务、视觉资源或实现方式。

## 主要使用场景

- 理解代码、解释实现，定位问题相关的文件和调用关系。
- 修改代码、修复缺陷，并执行测试或命令检查结果。
- 审查变更，查看差异，处理诊断或持续集成失败。
- 在多次交互之间延续工作，恢复会话、压缩上下文或撤销已跟踪的变更。
- 执行期间查看进展、审批操作、调整方向或取消任务。

场景描述产品支持的工作方式；是否完成某项具体任务，取决于上下文、模型能力、可用工具和验证结果。

## 功能范围

| 功能领域 | 产品能力 | 具体行为的权威出处 |
|---|---|---|
| 任务交互 | 提交问题与附件，接收流式回复、推理内容、工具活动和错误反馈 | [终端规范](../spec/terminal.md)、[会话规范](../spec/session.md) |
| 连续执行 | 多次模型推理与工具操作形成持续响应，支持审批、拒绝、失败和取消后的收尾 | [运行时规范](../spec/runtime.md)、[状态机规范](../spec/machine.md) |
| 执行干预 | 区分中途引导与排队输入，按约定接纳后续输入 | [终端输入规范](../spec/terminal.md#运行期间的输入) |
| 项目与工作区 | 选择项目，限制文件访问范围，并在恢复会话时恢复工作环境 | [工作区规范索引](../spec/workspace.md) |
| 开发工具 | 读取、搜索、修改文件，运行命令，查看版本控制差异及语言诊断，访问获准的网络资源 | [工具规范](../spec/tools.md) |
| 会话历史 | 保存、查找、恢复、重命名、删除和分支会话，压缩或重置上下文 | [会话规范](../spec/session.md)、[终端命令规范](../spec/terminal.md#命令) |
| 变更恢复 | 对已跟踪写入建立检查点，撤销时协调文件恢复与会话历史 | [会话撤销规范](../spec/session.md#撤销undo) |
| 模型与 Agent 选择 | 配置模型服务及 Agent 配置，选择可用工具与权限模式 | [配置规范](../spec/config.md) |
| 委派与扩展 | 向子 Agent 委派工作，接入外部工具、语言服务、技能和工作流扩展 | [会话规范](../spec/session.md#委派)、[工具规范](../spec/tools.md)、[配置规范](../spec/config.md#扩展) |

本表定义功能范围，不重复规定命令语法、配置字段或失败处理细节。

## 目标与进度的边界

本文件定义产品要实现的能力，不维护实时完成状态。[Gap](../gap.md)维护当前实现证据、验证范围与目标差距，[Flow](../flow.md)维护开发节点的状态和依赖。

列入功能范围不表示已经实现或验收。最终产品的目标场景、优先级与验收标准需要项目负责人明确，不能用现有代码反向定义目标。

## 产品边界

用户交互入口的范围由[软件架构](software-architecture.md#系统范围)规定。

- 工作区操作遵守授予的访问范围和权限策略，具体安全要求见[质量目标与约束](constraints.md#授权与工作范围)。
- 恢复会话依据保存的历史与工作环境，不承诺从外部操作中断的位置继续执行。
- 撤销覆盖已跟踪的变更，覆盖范围由会话规范规定。
- 对话压缩会损失未进入摘要的细节，恢复能力遵循会话规范。
