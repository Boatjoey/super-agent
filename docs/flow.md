# 开发推进 Flow

本文件用邻接表描述通往产品目标的未完成开发节点、当前状态和依赖关系。需要完成的工作及完成条件见 [gap](gap.md)，功能含义由设计与 Spec 定义。

这是项目开发工作的推进图，与 Agent 执行任务时的 Turn、Step 或运行时状态机不同，也不恢复按日期堆积的计划目录。

## 邻接表的含义

- 每一行是一个尚未完成的开发节点，ID 稳定；“后继节点”是该节点完成后可以参与解锁的直接下游。
- 边 `A → B` 表示 B 的完成依赖 A 的交付；B 有多个前驱时，必须全部验收完成才能进入正式实施。独立的调查和准备可以提前进行，但不算完成下游交付。
- 没有前驱的节点可以独立推进，当前入口是 D48。
- `—` 表示没有后继节点。依赖图不得出现环、未知节点或悬空引用；并行行进到汇合节点时采用“全部满足”的条件。
- 节点状态在本文件维护。状态改变不等于自动满足后继节点条件。
- 已完成的节点从本表移除，不保留归档；重开时按原 ID 恢复节点。

## 节点状态转移邻接表

| 当前状态 | 允许进入的状态 | 条件 |
|---|---|---|
| 待确认 | 待开始、阻塞 | 需求或取舍明确后进入待开始；存在无法推进的依赖时记录阻塞 |
| 待开始 | 进行中、阻塞 | 正式实施前确认前驱已完成及本节点范围明确 |
| 进行中 | 待验收、阻塞 | 交付物可检查时进入待验收；不能直接跳到已完成 |
| 待验收 | 已完成、进行中、阻塞 | 验收通过才能完成；失败返回进行中；无法验收记录阻塞 |
| 已完成 | 待开始 | 目标变化或发现回归时显式重开，并记录原验收失效原因 |
| 阻塞 | 待确认、待开始、进行中、待验收 | 写明阻塞解除的依据，返回适当状态；不得直接标记完成 |

“待确认”说明行为或验收还不明确；“阻塞”说明已知工作因为具体条件不能推进。缺少验证不能被当作成功，未开始不等于阻塞。

## 状态更新

开始节点时记录范围和开始依据；暂停推进时记录阻塞条件；转入待验收时提供可检查的实现或文档；完成时核对对应 Gap 的关闭条件并从本表移除节点。


发现新的独立工作时增加节点并关联 gap。节点拆分后保留其关系，验收与优先级发生变化时同步调整邻接表；不维护另一个没有状态的执行计划副本。

已完成的上游节点重开时，必须检查下游验收依据是否失效；受影响的下游节点应恢复后重开或转为阻塞，并记录原因，不能继续以失效的前置结论宣称完成。
