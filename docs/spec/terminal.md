# 终端行为规范

界面形态、布局、视觉层次与示例由 [UI 设计](../design/ui.md)定义，用户操作流程与反馈由 [UX 设计](../design/ux.md)定义。本文件负责终端输入输出、按键及渲染的精确行为，不复制界面方案。前端与 Agent 的命令、快照和通知契约由[应用接口规范](application-interface.md)定义。

## 输入输出

`TerminalApplication` 使用普通终端输入、标准输出和滚动历史，遵守 [UI 设计](../design/ui.md#对标目标与范围)确定的 Codex CLI 对标形态。已提交历史顺序追加，输入草稿、实时活动与状态可以原位更新，不进入全屏备用屏幕。输入采用 UTF-8，无效字节替换为 `�`，不得因此终止命令行。

终端输入读取跨平台：逐字符（cbreak）模式与按键名解析由 `tui/terminal_io.py` 抽象，POSIX 用 `termios`/`tty`/`select`，Windows 用 `msvcrt`，`TerminalApplication` 本身不持有平台分支。Ctrl+C 在 POSIX 经事件循环的 `add_signal_handler` 路由为 `ctrl+c`，在 Windows 经 `signal.signal` 的 `SIGINT` 处理器路由为同一键名。

回复、工具活动、错误和斜杠命令的已提交结果追加到标准输出，实时状态更新当前交互区。Rich 负责 Markdown 与 ANSI 渲染，不拥有终端生命周期。窗口宽度变化时重新布局当前交互区，保持草稿、当前选择和光标位置，不重放工具操作或重复追加历史。

不依赖框架的交互模型与会话端口出于兼容性保留在 `tui/` 下；包名不表示存在第二种产品入口。交互入口范围由[软件架构](../design/software-architecture.md#系统范围)规定。

## 流式输出与历史

助手文本随累积流式消息逐步展示，正式消息提交时完成同一条回复，不重复打印已输出文本。推理的视觉样式引用 UI 设计；工具结果和错误保持独立的历史条目。

流式输出与审批通知必须在到达时处理，不等待下一个输入提示才显示。通知流关闭不直接代表任务成功，结束条件以[应用接口规范](application-interface.md#已有流结束与失败处理)为准。

## 命令补全

在交互式终端中，输入 `/` 打开当前提示符附近的命令列表。继续输入按命令名前缀筛选；上、下方向键切换选择，Tab 补全，Enter 先补全选中的不完整名称，再次 Enter 执行。草稿不再是命令前缀时列表消失。

管道输入采用逐行模式，直接运行完整斜杠命令，不显示实时列表。两种模式都不进入备用屏幕。

## 审批与退出

审批选项的布局和文案由 [UI 设计](../design/ui.md#审批界面)定义。输入 `1` 提交允许一次，`2` 提交始终允许，`3` 提交拒绝；`y`、`a`、`n` 分别与之等价。提交时随决定带上该请求的标识；应用若不受理（请求已不再待决），终端显示拒绝原因而不是当作已生效，关联与失效处理遵循[应用接口规范](application-interface.md#已有审批与错误关联)。

EOF 退出；`Ctrl+C` 在有活跃轮次时发出取消，在空闲时退出。`/quit` 和 `/exit` 提供显式退出方式。发出取消与确认结束的区别见 [UX 设计](../design/ux.md#取消与结束)。

## 运行期间的输入

输入归属由[核心概念](../design/concepts.md#输入归属)规定，接纳时点由[运行时规范](runtime.md#轮次与步骤边界)规定。界面必须表达 steering 与排队提交两种意图，并按[目标输入契约](application-interface.md#目标输入契约)消费受理和接纳反馈。

目标提交键位如下，`Enter` 与 `Tab` 已按各自的归属接入应用接口：

| 输入上下文 | 操作 | 目标语义 |
|---|---|---|
| 空闲、普通非空文本 | `Enter` | 提交新轮次 |
| 执行中、普通非空文本 | `Enter` | 提交中途引导，关联当前 Turn，由应用在下一 Step 接纳 |
| 执行中、普通非空文本 | `Tab` | 排队到下一 Turn，不取消当前执行 |
| 命令名前缀或补全选择中 | `Tab`、`Enter` | 优先遵守命令补全规则，不将补全按键误发成普通输入 |
| 审批选择中 | 审批按键 | 优先处理当前审批，不将选择值作为任务正文 |
| 空白输入 | 普通提交动作 | 不创建空消息或新轮次 |

此处仅确定普通文本的运行中引导与排队，不扩展已有斜杠命令的运行条件。补全或审批上下文退出后，恢复原有草稿；输入处理与流式刷新不得相互覆盖。

运行中的 `Enter` 不再取消当前 Turn：输入交给 `TurnPort.steer`，被受理时草稿清空并显示“等待下一步”，被拒绝时草稿保留并显示原因。接纳与撤销由[应用接口规范](application-interface.md#已有通知契约)的两条通知报告。

运行中的 `Tab` 交给 `TurnPort.queue`：被受理时草稿清空、页脚显示“排队中”并列出待执行的输入，被拒绝（例如这一轮刚好结束）时草稿保留并显示原因。排队条目由应用持有的队列决定，终端只显示它，并在收到接纳或作废通知时移除对应条目：接纳时提示该输入成了第几轮，作废时说明它随取消一起丢弃。终端不自行启动排队的输入——续接由应用在一次提交内完成，因此页脚不会出现“已排队但永不执行”的条目。

取消（`Ctrl-C`、`Esc`）同时告知运行时，排队的输入随该轮取消一并丢弃，页脚据作废通知清空。以上交互的自动用例已覆盖受理、拒绝、接纳与作废；真实终端按键与竞态验收由 [gap](../gap.md#已知待完成工作) 与 [flow](../flow.md#开发节点邻接表)跟踪。

## 命令

斜杠命令与交互循环使用同一命令模型：

- 会话：`/clear`、`/compact`、`/sessions`、`/resume`、`/rename`、`/delete-session`、`/fork`、`/undo`。
- 权限与 Agent：`/permissions`、`/agent`、`/plan`、`/build`、`/mode`。
- 上下文：`/attach`、`/attachments`、`/memory`、`/memory on|off`、`/remember`、`/forget`、`/instructions`。
- 服务商：`/config`、`/config list`、`/config provider <name> <api_key> [model]`。
- 工作流：`/review`、`/diff`、`/fix-ci`、`/branch`、`/commit-message`、`/diagnostics`、`/export`、`/share`。
- 扩展：`/mcp`、`/commands`、`/skills`、`/plugins`。

具体用例通过应用接口执行，行为规则归相关领域 Spec。命令输出追加到历史；命令成功时清除之前的错误，命令失败时保留先前状态，因为错误具有展示优先级。

## 外观

配色、强调与视觉层次的权威定义见 [UI 终端视觉规则](../design/ui.md#终端视觉规则)。`NO_COLOR` 禁用颜色；关闭颜色后，文字标识与输出内容仍保留。

围栏代码块内的语法高亮可选择独立主题，配置方式见[配置规范](config.md#交互式命令行)。正文与状态的 ANSI 样式遵守 UI 设计，不能从语法主题推导整套界面颜色。
