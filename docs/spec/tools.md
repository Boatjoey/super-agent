# 工具

本文件定义工具注册、调用、访问控制及隔离行为。代码依赖约束见[模块职责](packages.md#代码依赖与接口约束)。

## 注册表

`tools.Registry` 保存可见工具。`tools.default_registry` 和 `tools.sandboxed_registry` 都要求应用在构造内建工具时注入一个工作区上下文；工具不得从进程工作目录自行推断策略。
`Registry.add` 原子合并动态发现的工具；只要名称为空、批次内重复或已注册，就拒绝整个批次，避免部分合并使工具集合不一致。`tools.default_registry` 构建内建工具；`tools.sandboxed_registry` 将同一组工具接到沙箱命令执行器。

## 内建工具

`default_registry` 包含十一个工具：

| 工具 | 用途 |
|---|---|
| `read_file` | 读取工作区文件，可指定行范围 |
| `list_files` | 列出工作区文件，可按 glob 模式筛选 |
| `search` | 用正则表达式搜索工作区文件 |
| `apply_patch` | 替换工作区文件中符合预期的文本 |
| `write_file` | 写入工作区文件，并创建父目录 |
| `run_command` | 执行工作区命令，可指定 cwd、超时和输出限制 |
| `git_status` | 展示 `git status --short` |
| `git_diff` | 展示 `git diff`，可指定路径 |
| `bash` | 获批后执行 shell 命令 |
| `web_search` | 获得网络审批后搜索公开网页 |
| `browser_fetch` | 抓取公开 HTTP(S) 页面，具备重定向、大小、超时和私有地址防护 |

`delegate` 由 `app`（`app/session.py`）注册，不由工具包注册。它在子 Agent 中执行任务并返回最终结果；子会话与工作树见 `session.md`。

每个面向文件的内建工具都通过注入的工作区上下文解析路径并检查读写权限。相对路径以工作区 cwd 为基准。包含判断使用规范路径和按路径组件进行的相对路径检查；对于待创建路径，还会检查最近的已存在祖先。字符串前缀和符号链接不能授予访问权限。LSP 文件读取使用相同策略，语言服务器进程在工作区 cwd 启动。严格命令沙箱也从同一注入上下文取得工作区绑定根目录，不使用进程 cwd。

权限策略在工作区检查之外再加一道：解析结果落在 cwd 之外即拒绝，绝对路径因此一律被拒。Windows 上 `/etc/passwd` 这类不带驱动器号的根路径会解析到当前驱动器（`C:\etc\passwd`），按绝对路径同等处理，不能靠形态差异绕过。

文件工具使用 `O_NOFOLLOW` 打开解析后的路径，因此在包含检查与打开之间，即使最后一个路径组件被替换为符号链接，也不能将读写重定向到工作区之外。更深层路径组件仍可能被替换，这是已接受的剩余风险。

`read_file` 和 `apply_patch` 拒绝超过 10 MiB 的文件，不将其加载到内存；`search` 将每行限制为 1 MiB，避免单条压缩或机器生成的长行中断扫描。`list_files` 和 `search` 跳过无法解析或读取的条目，包括指向工作区之外的符号链接，不使整个列举或搜索失败。`read_file` 按行拆分时把 CRLF 行尾当作行结束，不把回车符带进行内容。

注入的工作区是可切换的运行时绑定。成功恢复会话会替换经过校验的上下文，后续内建文件系统和命令调用使用恢复后的 cwd 与根目录。cwd 改变时，语言服务器客户端按需重连。MCP 服务器是通过配置启动的外部进程，不是文件系统策略适配器；工作区恢复不改变其生命周期。
高风险工具需要策略审批，除非当前模式允许直接执行。

命令工具默认使用工作区 cwd。模型指定的命令 cwd 必须解析为可读的工作区目录。工作区检查不是操作系统安全边界：shell 进程启动后，仅靠上下文无法阻止 `cat ~/.ssh/id_rsa` 等命令。启用时，下述独立的操作系统沙箱负责约束子进程文件系统访问。

## MCP

`tools/mcp` 通过标准输入输出使用 MCP，服务器字段见[服务器配置](config.md#服务器)。

- 发现的输入 schema 映射为 `protocol.ToolSpec`。
- 调用设有截止时间和输出上限。
- 发现的工具原子加入 `tools.Registry`，在统一权限策略下**始终视为高风险**，不受服务器自我声明影响。

应用控制器协调生命周期、动态注册表变更、回滚和配置的原子持久化。添加与删除操作原子更新 `settings.json`。扩展关闭由运行时 session 负责。

## LSP

`tools/lsp` 按[服务器配置](config.md#服务器)启动标准输入输出语言服务器并匹配文件扩展名。配置的服务器提供 `lsp_diagnostics`、`lsp_symbols`、`lsp_definition`、`lsp_references` 和 `lsp_outline`。诊断采用推送方式。

## 网络工具

`web_search` 和 `browser_fetch` 是高风险网络工具，使用统一权限流程。网页抓取只接受公开 HTTP(S) 目标，拒绝本地和私有 DNS 结果，限制重定向次数、响应大小和总耗时，并在不执行脚本的情况下提取页面文本。

## 沙箱

权限模式用于决定审批路径，**不是**安全边界。命令分类依赖文本启发式，可能出错，因此命令执行需要单独隔离。

在 Linux 上，`tools/sandbox_linux.py` 默认使用严格的 bubblewrap 隔离运行命令：

- 宿主根目录只读挂载。
- 工作区是唯一可写的宿主绑定目录。
- 临时目录和 home 目录均为临时环境。
- 网络遵循配置的网络策略（`permissions.network`）。
- `prlimit` 限制 CPU 时间、地址空间、进程数和打开文件数。

沙箱参数来自顶层 `sandbox` 配置，见 `config.md`。

严格模式**在条件不满足时拒绝执行**：缺少 `bwrap` 或 `prlimit` 就不运行命令。它们是 Linux 上的系统依赖，缺失时应用在启动阶段即拒绝启动，不会降级为无隔离运行；不受支持的平台同样必须显式设置 `sandbox.mode: off` 才能启动，此时命令以当前用户权限执行。安装方式见 [README](../../README.md#安装与启动)。
